# Контекст реализации: Project Deep Dive

Дата: 2026-05-11

## Что сделано
- Реализован этап `Project Deep Dive` из `docs/План улучшения сайта-резюме.md`.
- Добавлены 5 ключевых проектов с кейс-структурой: роль, сложность, проблема, решение, результат, чему научился, стек.
- Добавлены фильтры направлений: `SQL`, `1C`, `React`, `Backend`, `AI`, `Учебные проекты` + `Все`.
- Добавлена кнопка `Подробнее` с раскрытием деталей карточки.
- Изменена модель показа проектов: вместо карусели всех репозиториев показывается curated-набор ключевых кейсов.

## Измененные файлы
- `src/data/projectsData.js`
  - Новый источник данных для deep-dive карточек и фильтров направлений.
- `src/services/githubService.js`
  - Добавлен merge curated-проектов с GitHub-данными (stars, language, link, updatedAt).
  - Добавлен fallback на локальные curated-данные при сетевых ошибках/лимитах.
- `src/Projects.js`
  - Полностью обновлен UI секции проектов:
    - фильтрация по направлениям,
    - сетка карточек,
    - раскрытие подробностей по кнопке `Подробнее`.
- `docs/Tasks.md`
  - Отмечен выполненным пункт первого этапа.

## Принятые решения
- Для задачи этапа выбран отдельный curated-слой (`projectsData.js`), чтобы фиксировать качество кейсов и не зависеть полностью от описаний из GitHub.
- GitHub API продолжает использоваться для актуальных метаданных (stars/language/link), но контент кейсов контролируется локально.
- При ошибках GitHub API интерфейс не ломается: показывается подготовленный deep-dive набор.

## Проверка
- Выполнена сборка: `npm run build`.
- Сборка успешна, секция проектов корректно компилируется.

## Что можно улучшить далее
- Добавить мультиязычность полей deep-dive кейсов через `LanguageContext`.
- Вынести конфигурацию порядка/приоритета проектов в отдельную админ-структуру.
- Добавить мини-метрики результата (например, цифры по времени отклика, охвату, вовлеченности), где это уместно.
